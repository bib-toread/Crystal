# 02 · 通信协议

> 客户端与服务端之间的一切都是封包。本篇讲清楚封包的线上格式、序列化机制、注册分发、状态门禁、收发与广播，以及**端到端新增一个封包**的完整步骤与坑。
>
> 核心文件：`Shared/Packet.cs`、`Shared/ClientPackets.cs`、`Shared/ServerPackets.cs`、`Shared/Enums.cs`、`Server/MirNetwork/MirConnection.cs`、`Client/MirNetwork/Network.cs`。

## 1. 线上格式

每个封包是一个「长度前缀二进制帧」，固定 4 字节头：

```
[2字节 length (UInt16, 小端)] [2字节 id (Int16, 小端)] [payload...]
```

- `length` = 整帧总长（id + payload 的字节数 + 2），写出时先 `ms.SetLength(2)` 预留，最后回填（`Shared/Packet.cs:69-83`）。
- 解析端读 `length = ToUInt16(raw,0)`，`id = ToInt16(raw,2)`（`Shared/Packet.cs:19-20`）。
- 健壮性：不足 4 字节、或 `length > 缓冲区长度`（半包，还没收全）、或 `length < 2`（非法）都返回 null（`Shared/Packet.cs:17,22`）。半包会留在缓冲区等下次数据到达再拼。

## 2. 方向：`IsServer`

`Packet.IsServer` 是静态字段（`Shared/Packet.cs:6`），各进程启动时设一次：服务端 `Program.cs` 设 `true`，客户端设 `false`。`ReceivePacket` 据此选注册表方向（`Shared/Packet.cs:26`）：

- 服务端（`IsServer==true`）用 `GetClientPacket(id)` 把入站字节解析成「客户端→服务端」封包；
- 客户端用 `GetServerPacket(id)` 解析「服务端→客户端」封包。

**约定别名**：客户端封包类用 `using C = ClientPackets`，服务端封包类用 `using S = ServerPackets`。全代码库都这么写，见到 `C.Walk`/`S.ObjectWalk` 即知方向。

## 3. 封包类与读写约定

每个封包继承抽象 `Packet`，实现三件事：

```csharp
public sealed class Walk : Packet
{
    public override short Index => (short)ClientPacketIds.Walk;   // 来自枚举的 id
    public MirDirection Direction;
    protected override void ReadPacket(BinaryReader reader)  { Direction = (MirDirection)reader.ReadByte(); }
    protected override void WritePacket(BinaryWriter writer) { writer.Write((byte)Direction); }
}
```

读写用 `BinaryReader`/`BinaryWriter`，**顺序必须严格镜像**（写 A、B、C 就要按 A、B、C 读）。常见约定：

- **标量**：直接 `Write((byte)x)` / `ReadByte()`。
- **字符串**：`Write(string)` / `ReadString()`（`BinaryWriter` 自带长度前缀的 UTF-8）。
- **变长集合**：先写 `int count`，再循环写元素；读端先读 count 再循环读。例：`C.Chat` 先写消息，再写 `LinkedItems.Count` 然后逐个写（`Shared/ClientPackets.cs:295-320`）。
- **字节数组**：先写 `int 长度` 再写 bytes，如 `C.ClientVersion` 的 `VersionHash`（`Shared/ClientPackets.cs:14-22`）。

### 可选压缩

虚属性 `Compressed`（默认 false，`Shared/Packet.cs:8`）控制按封包类型压缩 payload（zlib）。数据量大的列表封包应开启，例如 `S.NPCGoods`（NPC 商品列表）`public override bool Compressed => true;`（`Shared/ServerPackets.cs:3077`）。对端按 `Compressed` 标志自动解压，无需额外协商。

### 观战转发开关

虚属性 `Observable`（默认 true，`Shared/Packet.cs:7`）控制该封包是否转发给观战者。私聊重写为不转发：`S.Chat` 的 `Observable => Type != WhisperIn && Type != WhisperOut`（`Shared/ServerPackets.cs:1153`）。

## 4. 注册表（最容易漏的一环）

`Shared/Packet.cs` 里两个大 `switch` 把 id 映射到「new 一个封包实例」：

- `GetClientPacket(short index)`（`Shared/Packet.cs:94`）—— 服务端用，id → `new C.Xxx()`。
- `GetServerPacket(short index)`（`Shared/Packet.cs:407`）—— 客户端用，id → `new S.Xxx()`。

**每个封包都必须在这里登记**。如果漏登记，`ReceivePacket` 拿到 null 后会把**整个接收缓冲清空**（`Shared/Packet.cs:31`，注释说明这是为防脏数据死循环），表现为「这个连接发了就再也收不到东西 / 直接断线」，且**没有任何异常**，极难排查。这是新增封包时的头号坑。

## 5. 服务端：从网络到游戏逻辑

服务端侧完整管线：**异步收 → 拼接缓冲 → 循环切帧 → 入 `_receiveList` → 游戏线程出队 → `ProcessPacket` 分发 → 路由到 `Player.*` / `Envir.*`**。

### 5.1 接收（IO 线程）

1. 监听器接受连接，构造 `MirConnection` 加入 `Envir.Connections`（带 IP 封锁/同 IP 数/总人数校验，`Server/MirEnvir/Envir.cs:3564`）。
2. 构造末尾 `BeginReceive()` 启动异步收（`MirConnection.cs:101`）。
3. `ReceiveData` 回调把字节追加到 `_rawData`（处理 TCP 粘包/半包），然后 `while ((p = Packet.ReceivePacket(_rawData, out _rawData)) != null) _receiveList.Enqueue(p);` 一次切出所有完整帧入队（`MirConnection.cs:129`）。`_receiveList` 是 `ConcurrentQueue`（IO 线程写、游戏线程读）。
4. 解析抛异常 → 该 IP 封 24 小时并断线（`MirConnection.cs:173`）。

### 5.2 消费与分发（权威游戏线程）

5. 游戏主循环每 tick 调 `Connections[i].Process()`（`Envir.cs:2076`）。
6. `Process()` 把 `_receiveList` 全部出队，每个刷新超时时间后 `ProcessPacket(p)`（`MirConnection.cs:242`）。
7. `ProcessPacket` 是按 `p.Index` 的大 `switch`（`MirConnection.cs:286`），强转封包类型后调对应私有处理方法。**每个处理方法首行几乎都是阶段门禁** `if (Stage != GameStage.Game) return;`（见第 7 节）。

### 5.3 三个落点实例

| 封包 | switch 分支 | 处理方法 | 落地 |
|---|---|---|---|
| `C.Walk` | `MirConnection.cs:334` | `Walk(C.Walk)` `:1164` | 冷却没到则塞回 `_retryList` 重试，否则 `Player.Walk(方向)` → `HumanObject.Walk` 校验后广播 `S.ObjectWalk` |
| `C.Chat` | `:340` | `Chat(C.Chat)` `:1183` | 长度防护后 `Player.Chat(...)`；观战阶段只接受 `@` 指令 |
| `C.Attack` | `:442` | `Attack(C.Attack)` `:1454` | 冷却没到进 `_retryList`，否则 `Player.Attack(方向, 技能)` |

> 账号类封包不路由到 `Player`，而是路由到单例 `Envir`：`C.Login → Envir.Login(p,this)`、`C.NewAccount → Envir.NewAccount`、`C.NewCharacter → Envir.NewCharacter`。

**动作重试队列 `_retryList`**：当玩家动作冷却（`ActionTime`/`AttackTime`/`SpellTime`）未到，`Walk/Run/Turn/Attack/RangeAttack/Harvest/Magic` 等会被暂存，本轮处理完再回灌下一轮重试（`MirConnection.cs:264`）。这实现了「服务端侧动作节流但不丢操作」。它与「断线重连」无关。

## 6. 服务端：发送与广播

### 6.1 构造与入队

构造一个 `S.Xxx`，用对象初始化器填字段，调 `connection.Enqueue(packet)`。`Enqueue` 把封包压入 `_sendList`，并且**若 `Observable` 为真，同时复制给所有观战者**（`MirConnection.cs:231`）。

### 6.2 批量发送

**Enqueue 只入队，不写 socket**。真正发送在游戏线程 `Process()` 尾部：把 `_sendList` 全部出队，多个封包 `GetPacketBytes()` 拼成**一个大字节块**，一次 `BeginSend` 异步发出（`MirConnection.cs:273`）。即一个 tick 内对同一连接的所有 Enqueue 被合并成一次 socket 写（`NoDelay=true` 关了 Nagle），降低延迟。

### 6.3 广播给周围玩家

广播 = 「枚举视野内玩家，逐个 `player.Enqueue(p)`」：

- `MapObject.Broadcast(Packet)`（`Server/MirObjects/MapObject.cs:408`）：遍历 `CurrentMap.Players`，对在 `Globals.DataRange` 视野内且不是自己的玩家 `Enqueue`。这是「发给周围玩家」的本体。
- `PlayerObject.Broadcast` 重写：先 `base.Broadcast`，再对移动/攻击/施法类封包额外发给本连接的观战者（`PlayerObject.cs:1587`）。

**命名约定**（贯穿全代码库，务必记住）：

- **发给自己**的封包无 `Object` 前缀：`S.UserLocation`、`S.HealthChanged`、`S.GainExperience`。
- **广播给别人看**的封包带 `Object` 前缀 + `ObjectID` 字段：`S.ObjectWalk`、`S.ObjectAttack`、`S.ObjectChat`、`S.ObjectMagic`。

## 7. `GameStage` 状态机

连接状态枚举 `None, Login, Select, Game, Observer, Disconnected`（`MirConnection.cs:13`）。每个处理方法用 `if (Stage != GameStage.Xxx) return;` 做门禁，**未达对应阶段的封包被静默忽略**——这是安全边界。

| 阶段 | 含义 | 允许的关键封包 |
|---|---|---|
| **None** | 刚连上，等版本 | 仅 `ClientVersion` |
| **Login** | 版本通过，登录态 | `NewAccount`、`Login`、改/解储藏密码 |
| **Select** | 已登录，选角态 | `NewCharacter`、`DeleteCharacter`、`StartGame`、`LogOut` |
| **Game** | 已进游戏 | 绝大多数玩法封包：`Walk/Attack/Magic/Chat/MoveItem/UseItem/CallNPC/BuyItem…` |
| **Observer** | 观战 | 受限子集：`Chat`(仅`@`指令)、`Inspect`、`Observe`、`GetRanking`、`LogOut` |
| **Disconnected** | 断开中 | `ProcessPacket` 开头整体短路 |

跨阶段无条件可处理的：`Disconnect`、`KeepAlive`。

**登录→选角→进入游戏的封包时序**：

```
[连接建立] 服务端主动下发 S.Connected
  C.ClientVersion ──► 校验通过 ──► S.ClientVersion{Result=1}; Stage: None→Login
  C.Login{账号,密码} ──► Envir.Login ──► S.LoginSuccess{角色列表}; Stage: Login→Select
  (可选) C.NewCharacter / C.DeleteCharacter
  C.StartGame{角色序号} ──► 创建 PlayerObject, Player.StartGame() ──► Stage→Game
  ... 游戏中 C.Walk/Attack/Chat/... ...
  C.LogOut ──► Player.StopGame(); Stage: Game→Select; S.LogOutSuccess
```

## 8. 连接防护（速览）

- **超时**：每收到封包刷新 `TimeOutTime = Time + Settings.TimeOut`（默认 10s）；超时 `Disconnect`。客户端靠 `KeepAlive` 维持。
- **IP 封锁**：新连接握手有 `IPBlockSeconds`（默认 5s）滑动门槛；同 IP 并发数 ≥ `MaxIP`（默认 5）拒绝；解析脏包或触发限流则封 **24 小时**。
- **限流**：`ReceiveData` 回调次数每 5 秒计数，超 `MaxPacket`（默认 50）封 IP 24h + 断线，并记录最近 10 个封包名辅助定位。
- **业务长度防护**：`Chat.Message` 超长、`CallNPC.Key` 超 30 字符等会直接断线。
- **无会话恢复**：协议层没有断线重连续传，重连即重走 `ClientVersion→Login→StartGame`；`Login` 时若账号已有连接会踢掉旧连接（顶号）。

> 另有独立的**状态端口**（3000，`MirStatusConnection`），只每 10 秒发一段 ASCII 文本报告在线人数/版本，供服务器列表查询，与游戏协议无关。

## 9. 客户端：收包与分发

`Client/MirNetwork/Network.cs` 是静态类：

- **收包（IO 线程）**：`ReceiveData` 追加到 `_rawData` 累积缓冲，循环 `Packet.ReceivePacket` 切帧入 `_receiveList`（`Network.cs:107`）。
- **分发（游戏线程）**：`Network.Process()`（由 `CMain.UpdateEnviroment` 每圈调用）出队，`MirScene.ActiveScene.ProcessPacket(p)`（`Network.cs:223`）。**所有封包按当前场景路由**，场景切换后自动由新场景处理。
- **发包**：业务代码任意处 `Network.Enqueue(packet)` 入 `_sendList`，由 `Process` 合并刷出。
- **场景 ProcessPacket 的层次**：各场景重写自己的 `switch`，`default` 回退到基类 `MirScene.ProcessPacket`（`Client/MirControls/MirScene.cs:171`），后者处理所有场景通用的数据字典更新类封包（`NewItemInfo`/`NewMonsterInfo`/`NewNPCInfo`…）。

## 10. 端到端新增一个封包（完整步骤）

以「新增一个客户端→服务端封包 `Foo`」为例，**顺序不强制但缺一不可**：

**① 枚举加 id（`Shared/Enums.cs`）**
在 `ClientPacketIds` 末尾追加 `Foo,`（服务端→客户端则加到 `ServerPacketIds`）。

> ⚠️ **绝对不要在枚举中间插入**。这两个枚举是隐式连续值（声明序号即数值），中间插入会平移后续所有 id，造成新旧两端 id 错位、把 A 解析成 B。**一律追加到末尾**。

**② 封包类（`Shared/ClientPackets.cs` 或 `ServerPackets.cs`）**
```csharp
public sealed class Foo : Packet
{
    public override short Index => (short)ClientPacketIds.Foo;
    public int SomeField;
    protected override void ReadPacket(BinaryReader reader)  { SomeField = reader.ReadInt32(); }
    protected override void WritePacket(BinaryWriter writer) { writer.Write(SomeField); }
}
```
读写顺序对称；变长字段「先 count 后循环」；payload 大可加 `public override bool Compressed => true;`。

**③ 注册表（`Shared/Packet.cs`）**
在 `GetClientPacket` 加 `case (short)ClientPacketIds.Foo: return new C.Foo();`（服务端→客户端加到 `GetServerPacket`）。**漏这步会被静默丢弃**（见第 4 节）。

**④ 服务端处理（`Server/MirNetwork/MirConnection.cs`）**
在 `ProcessPacket` 的 `switch` 加 `case (short)ClientPacketIds.Foo: Foo((C.Foo)p); break;`，实现 `private void Foo(C.Foo p)`。**首行加阶段门禁**（通常 `if (Stage != GameStage.Game) return;`）。需要回包 `Enqueue(new S.Xxx{...})`，需要广播走 `Player.Broadcast(...)`。

**⑤ 客户端处理（`Client/MirScenes/*.cs`）**
在会收到它的那个场景的 `ProcessPacket` 加分支（游戏内通常是 `GameScene.cs` 的大 `switch`）：`case (short)ServerPacketIds.Xxx: Xxx((S.Xxx)p); break;`，写处理方法更新模型/对话框/对象，渲染由主循环自动反映。客户端发起则用 `Network.Enqueue(new C.Foo{...})`。

## 11. 坑位清单

1. **忘记在 `Packet.cs` 注册 → 静默丢弃 + 连接被截断**。最隐蔽，无异常。
2. **枚举中间插入/删除 → id 整体平移、两端错位**。只追加到末尾；客户端和服务端各有一份枚举拷贝，必须保持一致。
3. **读写顺序/类型不对称 → `InvalidDataException` → 封 IP 24h**。开发期很容易把自己的测试 IP 封掉（解封：清 `Envir.IPBlocks` 或重启服务端）。
4. **版本校验分两套，别混淆**：
   - **客户端校验走哈希**：`Settings.CheckVersion` 开启时，`ClientVersion` 把客户端上报的 `VersionHash`（客户端 exe 的 MD5）与 `Settings.VersionHashes` 比对，不匹配就拒绝。协议有变更、客户端重新编译后需要**重新生成并配置哈希**，否则所有客户端被拒。
   - **`Envir.MinVersion=60`/`Version=117` 是存档库版本**（`Server.MirDB` 的兼容范围），与网络协议无关。
5. **大列表封包记得开 `Compressed`**，否则带宽暴涨。
