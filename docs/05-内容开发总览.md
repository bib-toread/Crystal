# 05 · 内容开发总览

> 第二册的入口。本篇讲清楚：游戏内容存在哪、用什么工具改、改完怎么生效，以及「新建一份内容」的标准工作流。后续 06–09 是各类内容的具体指南。
>
> 核心：服务端管理程序 `Server.exe`（`Server.MirForms/`）的各编辑窗体，以及 `Envir/` 数据目录。

---

## 1. 两类存储，决定两种改法

Crystal 的游戏内容分两类载体，**这是内容开发最重要的区分**：

| | 二进制库 `Server.MirDB` | 文本文件 `Envir/*` |
|---|---|---|
| 存什么 | 物品、怪物、地图、NPC放置、任务元数据、技能、商城、攻城、神龙 | NPC 脚本、掉落表、配方、任务正文、巡逻路线、名单、数值 |
| 怎么改 | **必须用编辑器**（GUI），不能手改 | **直接编辑文本**（也可手改），部分有 GUI 辅助 |
| 怎么生效 | 编辑器关窗 `SaveDB` 落盘；运行世界需重启重载 | 多数可「热重载」，无需重启 |

记住这条边界，后面每一类内容都会落到这两类之一（或两者配合）。

## 2. 编辑器：Server.exe 管理程序

服务端入口 `Server.MirForms/Program.cs` → `SMain` 窗体。启动时 `SMain_Load` 把二进制库读进**编辑实例 `Envir.Edit`**，成功后自动 `Envir.Start()` 启动游戏世界（`Envir.Main`）。

> **两个 Envir 实例**（关键）：
> - `Envir.Main` = 运行中的权威世界（在线玩家、实时状态）。
> - `Envir.Edit` = 所有内容编辑器读写的对象。
>
> 编辑器改的是 `Envir.Edit`，关窗 `SaveDB()` 写入 `Server.MirDB` 文件；运行世界 `Envir.Main` 只在**启动时 `LoadDB`** 读这个文件。所以**改了进库的内容，要重启服务器**（让 `Envir.Main` 重新 `LoadDB`）才在游戏里生效。

主菜单结构（已汉化）：

| 顶级菜单 | 子项 |
|---|---|
| **控制** | 启动/停止/重启服务器、清除封禁IP、关闭 |
| **重载** | NPC、掉落、行消息 —— **热重载文本文件，不停服** |
| **账号** | 账号列表、市场、名单 |
| **数据库** | 地图、物品、怪物、NPC、任务、技能、商城、配方 |
| **配置** | 服务器配置、平衡配置 |
| **系统** | 神龙、采矿、公会、钓鱼/邮件/商品/精炼/关系/师徒/宝石/英雄、攻城、刷新计时、怪物调试、掉落编辑器、角色 |

## 3. 编辑窗体怎么工作（统一模式）

物品/怪物/NPC/任务/地图等编辑窗体是高度一致的模板：

1. **读列表**：窗体打开时读 `Envir.Edit` 上对应的 `*InfoList`（如 `ItemInfoList`/`MonsterInfoList`）。
2. **新增**：点 Add → `Envir.Create*Info()`，在列表末尾 new 一个对象并把全局自增索引 +1。
3. **修改**：列表选中后，右侧控件的 `TextChanged`/`SelectedIndexChanged` 事件**直接把值写回选中对象的字段**（无「应用」按钮）；解析失败把输入框染红。支持多选批量改。
4. **删除**：Remove → 确认 → `Envir.Remove(info)` 从列表移除。
5. **持久化**：改动只在内存，**关闭窗体时 `FormClosed` 统一 `Envir.SaveDB()`** 把整个 `Envir.Edit` 序列化进 `Server.MirDB`（写前自动备份到 `Back Up/`）。

> 含 NPC/任务的窗体有个**桥接**：它们的 `FileName` 字段绑定一个文本脚本名，「打开脚本」按钮会在 `Envir/NPCs/` 或 `Envir/Quests/` 下打开/创建同名 `.txt`。即「二进制里的放置定义」+「文本里的逻辑脚本」两段式。

## 4. 生效方式速查

| 改了什么 | 怎么生效 |
|---|---|
| NPC 脚本 (`Envir/NPCs/*.txt`) | 菜单「重载 → NPC」，热生效 |
| 掉落 (`Envir/Drops/*.txt`) | 菜单「重载 → 掉落」，热生效 |
| 跑马灯/行消息 | 菜单「重载 → 行消息」 |
| 配方 (`Envir/Recipe/*.txt`) | 重启（或随其它重载，视实现） |
| 进库内容（物品/怪物/地图/NPC放置/任务元数据/技能/商城） | 编辑器关窗已 `SaveDB`，**重启服务器**让 `Envir.Main` 重新 `LoadDB` |
| 配置 (`Configs/Setup.ini`) | 多数重启生效；部分配置窗体即时 |

**经验法则**：纯文本内容（NPC/掉落/配方）优先用「重载」热生效；进二进制库的内容改完重启服务器。

## 5. 图档前提（容易忽略）

怪物、物品、NPC、装备外观都需要对应的 `.Lib` 图档资源（由 `Image`/`Shape` 等字段按整数 index 引用）。**图档由社区分发，不在本仓库**。新增有新外观的内容前，要先用 `LibraryEditor` 把美术做进 `.Lib`，拿到它的 index，再在数据里引用。复用已有外观（用现成 index）则无需动图档。

## 6. 新建一份内容的标准工作流

以「做一套新地图 + 新怪物 + 掉落新装备 + 一个发放任务的 NPC」为例，串起整个流程：

```
① 备图档(如需新外观)
   用 LibraryEditor 把地图/怪物/装备/NPC 美术做进 .Lib,记下各自 index

② 建基础数据(GUI,进二进制库)
   数据库 → 物品:  新增 ItemInfo(装备/材料),设 Type/Shape/属性
   数据库 → 怪物:  新增 MonsterInfo,设 Image/AI/属性,填 DropPath
   数据库 → 地图:  新增 MapInfo,FileName 指向 Maps/ 下的 .map,
                   加安全区(含出生点 StartPoint)与刷怪点 Respawn(选刚建的怪)

③ 配掉落(GUI→文本)
   系统 → 掉落编辑器: 给怪物挑物品、设掉率 → 生成 Envir/Drops/{怪名}.txt

④ 建 NPC 与脚本(GUI+文本)
   数据库 → NPC: 新增 NPCInfo(选地图/坐标/FileName) → 「打开脚本」
   → 生成 Envir/NPCs/xxx.txt → 手写 [@MAIN] 等段落逻辑

⑤ 建任务(GUI+文本,如需)
   数据库 → 任务: 新增 QuestInfo 元数据 + 「打开脚本」生成任务正文模板手写
   NPC 脚本里用 ACT 命令开启/检查任务

⑥ 生效
   纯文本(NPC/掉落)用「重载」热加载;
   进库内容(物品/怪物/地图/NPC放置/任务元数据)→ 重启服务器
```

各步骤的字段细节、脚本写法、AI 编写见后续各篇：

- **物品/技能** → [06-物品与技能](06-物品与技能.md)
- **怪物/AI/刷怪/掉落** → [07-怪物与AI](07-怪物与AI.md)
- **NPC 脚本/任务** → [08-NPC脚本与任务](08-NPC脚本与任务.md)
- **地图/玩法系统** → [09-地图与玩法系统](09-地图与玩法系统.md)

## 7. 已知坑

- **编辑 `Envir.Edit`、运行 `Envir.Main`**：在编辑器里改完没重启，游戏里看不到变化是正常的，不是 bug。
- **任务多选批量编辑有已知问题**：`QuestInfoForm` 源码中作者自标了几处 BUG（多选时 FlagMessage/RequiredQuest 比较、TimeLimit 处理可疑），建议任务**逐条编辑**而非多选批量。
- **物品窗体的导入/导出已被注释禁用**，怪物/NPC/任务的导出 `.txt`/`.csv` 仍可用。
- **删改内容注意引用**：删一个被掉落/任务/配方/刷怪引用的物品或怪物会留下悬空引用，删除前先清理引用方。
