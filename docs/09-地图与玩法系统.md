# 09 · 地图与玩法系统

> 怎么新增地图、配安全区/传送/刷怪/矿区，玩法系统（行会/攻城/神龙等）在哪里，以及**怎么新增一个全局定时世界事件**。
>
> 相关源码：`Server/MirDatabase/MapInfo.cs`/`SafeZoneInfo.cs`/`MovementInfo.cs`/`RespawnInfo.cs`、`Server/MirEnvir/{Envir,Map,Dragon,Robot,RespawnTimer}.cs`、`Server.MirForms/Database/MapInfoForm.cs`、`Server.MirForms/VisualMapInfo/`。

## 第一部分 · 地图 MapInfo

`MapInfo`（`Server/MirDatabase/MapInfo.cs:6`）= 一张地图的定义，存进 `Server.MirDB`。它**内嵌多组子列表**，一张图的安全区/传送/刷怪/矿区都挂在它下面。

| 字段 | 含义 |
|---|---|
| `Index` | 主键（自增） |
| `FileName` | 对应 `Maps/` 下的 `.map` 文件名（地形数据） |
| `Title` | 地图标题（玩家可见） |
| `MiniMap`/`BigMap` | 小地图/大地图图档编号 |
| `Light` | 光照（白天/黑夜/常亮等） |
| `Music` | 背景音乐编号 |
| `NoTeleport`/`NoRecall`/`NoReconnect`/`NoFight`/`Fight`/`Fire`/`Lightning` … | 一大批地图规则开关 |
| `SafeZones` | 安全区列表（`SafeZoneInfo`） |
| `Movements` | 传送点列表（`MovementInfo`） |
| `Respawns` | 刷怪点列表（`RespawnInfo`） |
| `NPCs` | 该图 NPC（`CreateMap` 时按 `NPCInfo.MapIndex` 回填） |
| `MineZones` | 矿区列表 |

> `.map` 文件是地形（格子可走性/图块），由社区地图编辑器制作，不在本仓库；`MapInfo` 是「这张地形之上的游戏规则与布置」。

### 新增一张地图的步骤

1. 把 `.map` 文件放进 `Maps/`。
2. 菜单「数据库 → 地图」Add 新增 `MapInfo`，`FileName` 填 `.map` 文件名（不含扩展名），设 `Title`/`Light`/`Music` 和需要的 `NoXxx` 规则。
3. 加**安全区**（至少一个含出生点，见下）。
4. 加**刷怪点**（见 [07 §4.1](07-怪物与AI.md#41-刷怪-respawninfo)）。
5. 加**传送点**连接其它地图。
6. 放 NPC：在 `NPCInfo` 里把 `MapIndex` 指向该图，`CreateMap()` 会自动回填。
7. 关窗 `SaveDB`，**重启服务器**。

## 第二部分 · 地图元素配置

都在「数据库 → 地图」选中地图后操作，子元素也随 `MapInfo` 存进 `Server.MirDB`。

### 2.1 安全区 SafeZoneInfo

「Add 安全区」→ 设坐标 `X/Y`、范围 `Size`、是否 `StartPoint`（出生点）。

- 安全区内免战（攻击被阻止）。
- **`StartPoint=true` 的安全区是玩家出生/复活点**。`CanStartEnvir()`（[03 §1.2](03-服务端架构.md#12-workloop-主循环)）会校验全服至少有一个起始点，否则服务器拒绝启动。

### 2.2 传送点 MovementInfo

「Add 传送」→ 设源坐标 + 目标地图 + 目标坐标。玩家踩到源格子即被传送到目标。双向传送要在两张图各加一个。

### 2.3 刷怪点 RespawnInfo

见 [07 §4.1](07-怪物与AI.md#41-刷怪-respawninfo)。可用文字表单逐条加，也可用可视化编辑器（下节）。

### 2.4 矿区 MineZone

「Add 矿区」→ 设区域 + 矿物类型。玩家在矿区可挖矿（配合 `CanMine` 物品/采矿系统）。

### 2.5 可视化地图编辑 VForm

`MapInfoForm` 里有按钮启动可视化编辑器 `VForm`（`Server.MirForms/VisualMapInfo/VForm.cs`）：它读取 `Maps/` 的真实地图图片，**在图上拖拽摆放刷怪点/矿区**，关闭时把面板上的控件回写成 `RespawnInfo`/`MineZone` 重建该地图的列表，随后 `MapInfoForm` 关闭触发 `SaveDB`。比纯文字坐标直观得多，推荐用它布刷怪。

## 第三部分 · 玩法系统概览

这些是引擎自带的大型玩法系统，各有数据/配置入口。大多数**配置在编辑器、逻辑在引擎**，扩展它们属于改引擎（参考对应源码）。

| 系统 | 配置入口 | 引擎/数据 |
|---|---|---|
| 行会 Guild | 系统→公会；NPC 脚本 `[@CREATEGUILD]` | `GuildInfo`/`GuildObject`，存 `Guilds/*.mgd` |
| 攻城/沙巴克 Conquest | 系统→攻城（`ConquestInfoForm`） | `ConquestInfo`/`ConquestObject`，存 `Conquests/*.mcd`；`Envir.Process` 每 10s 推进 |
| 神龙 Dragon | 系统→神龙（`DragonInfoForm`） | `DragonInfo`/`Dragon`，独立 `Process` |
| 采矿 Mining | 系统→采矿；地图矿区 | 矿区 + `CanMine` 物品 |
| 钓鱼 Fishing | 系统→钓鱼 Tab；`Envir/Drops/00Fishing.txt` | 钓鱼竿物品 + 钓鱼掉落 |
| 邮件 Mail | 系统→邮件 Tab；脚本 `SENDMAIL` | `MailInfo`，挂角色 |
| 婚姻/师徒 | 系统→关系/师徒 Tab | 挂 `CharacterInfo` |
| 英雄 Hero | 系统→英雄 Tab；脚本 `[@CREATEHERO]` | `HeroInfo`/`HeroObject`（半 AI 随从） |
| 商城 GameShop | 数据库→商城（`GameShop`） | `GameShopItem`，进 `Server.MirDB` |
| 拍卖行 Market | 账号→市场；脚本 `[@MARKET]` | `AuctionInfo`，`Envir.Process` 每 10 分钟结算 |
| 配方/制造 Recipe | 数据库→配方；脚本 `[@CRAFT]` | `Envir/Recipe/*.txt` |

平衡性数值（掉率/经验倍率、稀有度系统、休整经验等）在「配置 → 服务器/平衡」窗体，写进 `Configs/Setup.ini`（见 [03 §1 配置](03-服务端架构.md#15-启动加载与持久化概览)）。

## 第四部分 · 新增全局定时世界事件

这是「加自定义玩法系统」最常见的需求（如每天 20:00 开红包雨、每小时刷世界 BOSS、整点全服公告）。

### 4.1 首选挂载点：`Envir.Process()`

所有「世界级周期逻辑」都集中在 `Envir.Process()`（`Envir.cs:2309`），主循环每迭代调一次。**照抄现有模式即可**：

```csharp
// 1) 在 Envir 加一个字段(参照 :200 附近的 warTime/guildTime/... 字段组)
private long myEventTime;

// 2) 在 Process() 里加一段(参照 :2317 起的写法)
if (Time >= myEventTime)
{
    myEventTime = Time + Settings.Minute * 30;   // 每 30 分钟
    DoMyWorldEvent();                            // 你的逻辑
}
```

现成可参照的范例（都在 `Envir.Process()` 内）：行会战 `warTime`、攻城 `conquestTime`(每10s)、租赁到期 `rentalItemsTime`、拍卖 `auctionTime`、刷怪节拍 `spawnTime`、机器人 `robotTime`、脚本计时器清理 `timerTime`。

### 4.2 按需求选挂法

| 需求 | 挂法 |
|---|---|
| 按真实日历（每天20:00、每周一） | 用 **`Robot`** 系统（`Robot.cs`）：在 NPC 脚本里写 `(月,日,时,分,页)`，到点自动 `Call` 指定脚本段。最适合「每天定点开活动」，无需改代码 |
| 每日重置（清日常、每日签到） | 挂进 **`ProcessNewDay()`**（`Envir.cs:4849`），自然日切换时对所有角色执行 |
| 按在线人数自适应的刷新节拍 | 参照 **`RespawnTimer`**（`RespawnTimer.cs`），按人数动态缩短间隔 |
| 独立慢周期子系统（自带状态/存档） | 参照 **`Dragon`**（`Dragon.cs`）：做成独立 `XxxSystem` 类，自持 `ProcessTime` 节流，在 `StartEnvir` 实例化、主循环加一行 `XxxSystem?.Process()`（仿 `DragonSystem?.Process()` `Envir.cs:2143`） |
| 一次性延迟任务 | 用 `Timer`（`Envir.Timers`）或对象级 `ActionList`/`DelayedAction` |

### 4.3 注意事项

- `Envir.Process()` 跑在**主线程**，这里能安全访问玩家/行会/地图等全局集合；**不要**把世界事件逻辑放进怪物 `ThreadLoop`（工作线程）。
- 节流用 `Time`（Stopwatch 毫秒）；需要日历语义（整点/日期）才用 `Now`。
- 若事件需要存档（如攻城/龙的状态），仿 [03 §5.4](03-服务端架构.md#54-版本兼容新增字段必读)在 `SaveDB`/对应 Save 里加序列化，`LoadDB` 按 `LoadVersion >= 新版本号` 兼容读取，并把 `Envir.Version` 自增。
- 用脚本能做的（定点开活动、刷怪、发奖励）**优先用 `Robot` + NPC 脚本**，不必改引擎；只有脚本表达不了的复杂逻辑才落到 `Envir.Process()` 写代码。

### 4.4 示例：每小时全服刷一只世界 BOSS

最省事的做法是**纯脚本**（`Robot` 系统）：

```
; 在某个机器人脚本(如 00Robot)里
[@HOURLYBOSS]
#IF
#ACT
MONCLEAR 玛法世界 ; 先清掉上一只(可选)
MONGEN 远古魔龙 1 ; 在指定地图刷一只
GLOBALMESSAGE 世界BOSS【远古魔龙】已降临玛法世界！

; 在机器人时间表里登记：每小时 0 分调用 [@HOURLYBOSS]
; 形如 (*,*,*,0,@HOURLYBOSS)  —— 具体语法见 Robot.cs / 现有机器人脚本
```

需要更复杂的判定（如按当前在线人数决定 BOSS 强度）才考虑在 `Envir.Process()` 写 C# 代码。

## 小结：内容开发的两条主线

到此第二册讲完。回顾贯穿始终的两条边界（见 [05](05-内容开发总览.md)）：

1. **数据 vs 代码**：物品/怪物属性、地图布置、掉落、对白、任务目标都是**数据**（编辑器/文本，改完重载或重启）；怪物 AI 行为、技能效果、脚本命令、世界事件逻辑是**代码**（改 C# 重新编译）。
2. **二进制库 vs 文本文件**：进 `Server.MirDB` 的内容必须用编辑器、改完重启；`Envir/` 下的文本（NPC 脚本/掉落/配方/任务正文）可直接改、多数能热重载。

先想清楚你要做的内容落在哪条线的哪一侧，就知道该开编辑器、改文本、还是写代码了。
