# 04 · 客户端架构

> 客户端是 WinForms + SlimDX(DirectX9) 的渲染程序，只做表现层。本篇分：主循环、图形栈、图档系统、场景控件框架、对象表现层、玩法 UI↔封包闭环。
>
> 核心文件：`Client/Forms/CMain.cs`、`Client/MirGraphics/{DXManager,MLibrary}.cs`、`Client/MirControls/{MirScene,MirControl}.cs`、`Client/MirScenes/{LoginScene,SelectScene,GameScene}.cs`、`Client/MirObjects/*.cs`、`Client/MirNetwork/Network.cs`。

---

## 第一部分 · 主循环与图形栈

### 1.1 Application.Idle 驱动的游戏循环

客户端**不用固定定时器**，靠 WinForms 的 `Application.Idle` 在消息泵空闲时持续回调（`CMain.cs:54` 注册）。循环体（`CMain.cs:102`）是 `while (AppStillIdle)` 紧循环——只要 Win32 消息队列没有待处理消息就一直转：

```
UpdateTime();              // Time = Timer.ElapsedMilliseconds (统一毫秒时基)
UpdateEnviroment();        // 逻辑更新(每圈都做)
if (IsDrawTime()) {        // 渲染节流
    RenderEnvironment();
    UpdateFrameTime();     // FPS 统计
}
```

**`UpdateEnviroment()`（逻辑，每圈执行）**（`CMain.cs:357`）：每秒一次 `DXManager.Clean()` 回收闲置纹理 → **`Network.Process()`**（收发网络、把封包派发给当前场景）→ `MirScene.ActiveScene.Process()`（当前场景逻辑）→ 更新动画控件 → 鼠标提示/调试标签。

**`RenderEnvironment()`（渲染，受限频）**（`CMain.cs:385`）：若设备丢失先尝试恢复并返回；否则固定的 DirectX9 一帧模板：

```
Device.Clear(黑) → BeginScene → Sprite.Begin(AlphaBlend)
→ SetSurface(MainSurface) → ActiveScene.Draw()
→ Sprite.End → EndScene → Present
```

**FPS 控制**：`IsDrawTime()`（`CMain.cs:345`）用 `1000 / Settings.MaxFPS`（默认 100）做渲染限频。**逻辑跑满空闲循环，渲染被限频**——这是「逻辑高频、渲染限频」的解耦。`Settings.FPSCap` 决定 D3D 是否等垂直同步。

**时间**：全局 `Stopwatch Timer`，`Time = Timer.ElapsedMilliseconds`（`CMain.cs:325`）是客户端统一时基，所有动画/CD/超时都基于它。

**输入**：构造函数订阅全套鼠标键盘事件，处理器只做少量全局状态维护（Shift/Alt/Ctrl、鼠标坐标、Alt+Enter 全屏），然后**统一转发给 `ActiveScene.On*`**——输入入口在窗体，分发权交给当前场景。

### 1.2 DXManager 图形栈

`Client/MirGraphics/DXManager.cs` 是 DirectX9 的全局静态封装，核心对象都是 `static`：`Device`、`Sprite`、`Line`、`MainSurface`/`CurrentSurface`。

- **初始化 `Create()`**（`:58`）：建 `PresentParameters`（后台缓冲格式、尺寸取 `Settings.ScreenWidth/Height`、窗口/全屏），探测设备能力选硬件/参考设备，创建 `Device`，加载纹理和像素着色器。
- **Sprite 批量绘制**：`Sprite` 是所有 2D 绘制的核心，每帧 `Begin/End` 包裹。统一入口 `Draw()`（`:252`）= `Sprite.Draw(texture, sourceRect, position, color)` 并自增 `DPSCounter`。
- **状态切换前必须 `Sprite.Flush()`**：sprite 是批处理的，改透明度/混合/着色器/渲染目标前必须刷出已积压批次，否则状态会错误地作用到之前的图元。`SetOpacity`/`SetBlend`/`SetGrayscale`/`SetSurface` 都遵守这点。
- **离屏渲染到纹理**：`SetSurface()`（`:219`）切换渲染目标前先 `Flush`。控件/场景/地图都先画进自己的 `RenderTarget` 纹理再贴回主表面，这是控件缓存机制的基础。
- **设备丢失处理**（DirectX9 经典问题，Alt+Tab/改分辨率触发）：渲染时捕获 `Direct3D9Exception` → 置 `DeviceLost=true`；下帧 `AttemptReset()`（`:258`）`TestCooperativeLevel`，`DeviceNotReset` 时 `ResetDevice()`（先释放所有 `Pool.Default` 资源，`Reset` 后重建）。`Pool.Managed` 的图档纹理由运行时自动恢复，无需手动重建。

### 1.3 .Lib 图档系统（MLibrary / MImage）

`Client/MirGraphics/MLibrary.cs` 定义图档库容器、单帧图像、全局注册表。

- **全局注册表 `Libraries`**（`:10`）：把所有 `.Lib` 资源声明为静态 `MLibrary` 字段，路径基于 `Settings.DataPath`（`.\Data\`）：UI 类、技能特效、物品、角色装备分职业数组（`CArmours`/`AWeapons`/`CHair`…）、怪物 `Monsters[]`、地图图档 `MapLibs[]`。
- **两阶段加载**：构造时同步加载登录/选人必需的少量库，其余海量库由后台线程异步 `Initialize()`，用进度条显示。
- **懒加载**：`.Lib` 文件保持打开但不全读入内存；`CheckImage(index)`（`:557`）发现某帧未加载时定位到该帧偏移读 `MImage`，未建纹理则 `CreateTexture` 上传 GPU。
- **`MImage` 单帧贴图**：头部含 `Width/Height`、绘制偏移 `X/Y`、阴影、`HasMask`（染色装备的第二层蒙版）。`CreateTexture()`（`:905`）建 `Pool.Managed` 纹理，GZip 解压像素直接写进锁定的纹理内存。绘制后续 `CleanTime`，长期未用被 `DXManager.Clean()` 自动卸载省显存。
- **按 index 绘制**：`MLibrary.Draw(index, point, colour)` 重载组（`:640`）：`CheckImage` 懒加载 → 屏外剔除 → `DXManager.Draw`。变体支持偏移、半透明、加法混合 `DrawBlend`（特效/光）、蒙版染色 `DrawTinted`、缩放。

> **「图档库 + 整数 index」是贴图寻址的统一语言**：UI 控件持有 `Library + Index` 画自己；角色按职业/动作/方向算出 `Libraries.CArmours[…]` 的具体 index；物品格子用 `Libraries.Items.Draw(item.Image, …)`。

## 第二部分 · 场景与控件框架

### 2.1 树形结构

一切可视元素都是 `MirControl`（`Client/MirControls/MirControl.cs:8`），通过 `Parent`/`Controls` 形成树。`MirScene`（`MirScene.cs:9`）是树根，是「占满全屏的特殊控件」。`DisplayLocation` 递归累加父坐标得屏幕绝对坐标，`Visible`/`Enabled` 沿父链与运算。

### 2.2 绘制（离屏缓存 + 脏标记）

- 每个控件可把自身渲染进一个 `RenderTarget` 纹理 `ControlTexture` 缓存，`DrawControl()` 把缓存纹理贴到当前表面。
- **脏标记 `TextureValid`**：属性变化（颜色/尺寸/位置/子控件增删）就 `Redraw()`，沿父链 `TextureValid=false`，下帧才重建——避免每帧重绘所有控件，只重绘「脏」子树。
- 递归绘制：`Draw()` = `BeforeDrawControl → DrawControl → DrawChildControls → DrawBorder → AfterDrawControl`，子控件正序遍历，列表末尾=最上层。

### 2.3 事件分发（命中测试 + 冒泡）

- 窗体把原始事件交给 `ActiveScene.On*`。
- `OnMouseMove` **逆序**遍历子控件（从最上层往下）找第一个命中的递归下去；无命中则把自己设为 `MouseControl`。
- 两个全局静态：`MouseControl`（当前悬浮）与 `ActiveControl`（当前激活/按下）。
- 键盘事件逆序向子控件传递，`e.Handled` 可中断冒泡。

### 2.4 三大场景与切换

全局唯一 `MirScene.ActiveScene`（`MirScene.cs:11`），初值 `LoginScene`。切换统一为 `ActiveScene = new XxxScene(); Dispose();`（旧场景递归释放控件树）。

| 场景 | 职责 |
|---|---|
| **LoginScene** | 连服、版本校验、登录/注册/改密。处理 `Connected/ClientVersion/Login*/NewAccount` |
| **SelectScene** | 角色列表/新建/删除/选择。`StartGame` 成功后按服务器分辨率切到 GameScene |
| **GameScene** | 游戏主场景，最庞大。持有 `MapControl` 和几十个对话框，`ProcessPacket` 是巨型 switch（`GameScene.cs:1340`），处理几乎所有游戏内封包 |

> **命名陷阱**：`MapControl`（地图控件，含 `M2CellInfo` 格子系统，是地图对象渲染的核心）**定义在 `GameScene.cs` 内部**，不是独立文件。

### 2.5 网络分发

`Network.Process()`（游戏线程，每圈调用）核心循环（`Network.cs:223`）：

```
while (_receiveList 非空) {
    _receiveList.TryDequeue(out Packet p);
    MirScene.ActiveScene.ProcessPacket(p);   // 交给当前场景
}
```

**所有封包按当前 `ActiveScene` 路由**。各场景重写自己的 `ProcessPacket`，`default` 回退基类处理通用的数据字典更新封包（`NewItemInfo`/`NewMonsterInfo`…）。

## 第三部分 · 对象表现层

### 3.1 客户端对象层级

客户端有自己的一套对象（与服务端同名但只管表现），基类 `MapObject`（`Client/MirObjects/MapObject.cs:10`）：

| 类 | Race | 职责 |
|---|---|---|
| `PlayerObject` | Player | 其他玩家：分层身体/武器/发型/坐骑/翅膀 |
| `UserObject : PlayerObject` | — | **本机玩家自己**，多输入/技能释放 |
| `HeroObject` / `UserHeroObject` | Hero | 英雄 |
| `MonsterObject` | Monster | 怪物，按图像枚举选图档库 |
| `NPCObject` | Merchant | NPC，含任务图标 |
| `ItemObject` | Item | 地面掉落物/金币 |
| `SpellObject` | Spell | 落地持续法术（火墙/毒云/陷阱） |

基类强制 `Process()`（推进状态/算坐标）、`Draw()`（出图）、`MouseOver()`（命中测试）。对象构造时注册进 `MapControl.Objects`（按 ObjectID 的字典）并按格子挂到 `CellInfo`。静态全局 `User`（本机玩家）、`MouseObject`/`TargetObject`/`MagicObject` 自动按 ID 解析。

### 3.2 「动作/朝向 → 图档帧」核心公式

所有对象绘制都依赖同一公式（在各自 `Process()` 算 `DrawFrame`）：

```
DrawFrame = Frame.Start + (Frame.OffSet * (byte)Direction) + FrameIndex
```

- `Frame.Start`：该动作在图档中的起始帧号；
- `Frame.OffSet = Count + Skip`：一个朝向占用的帧跨度；
- `Direction`（8 向 0–7）× OffSet → 定位到当前朝向那一段；
- `FrameIndex`：动作内当前帧，由动画推进递增。

### 3.3 帧动画系统 Frames

`Client/MirObjects/Frames.cs`：

- `Frame`（`:203`）= 一个动作的帧定义：`Start, Count, Skip, Interval` + 翅膀/特效层的并行字段 + `Reverse`(倒放,复活用) + `Blend`(叠加)。
- `FrameSet : Dictionary<MirAction, Frame>` = 一类对象的全部动作表，键是动作枚举 `MirAction`（站立/行走/攻击/受击/死亡…）。
- 预置：`FrameSet.Player`（玩家全套含职业/坐骑/钓鱼专用段）、`FrameSet.DefaultMonster`（通用怪物模板，绝大多数怪物用）、`FrameSet.DefaultNPC`。
- **怪物帧表优先从图档库自带读取**：`Frames = BodyLibrary.Frames ?? FrameSet.DefaultMonster`（`MonsterObject.cs:276`）——`.Lib` 可内嵌每动作帧定义，没有才回退默认。这是新增怪物的核心扩展点。

**动画推进**：用 `NextMotion`（毫秒时间戳）节流，`if (CMain.Time >= NextMotion)` 才推进一帧。动作排队用 `ActionFeed`（`List<QueuedAction>`）：服务端封包把动作塞进队列，`SetAction()` 按序取出。远程对象 `ActionFeed` 堆积时 `SkipFrames` 跳帧快进避免延迟累积。移动时按 `FrameIndex/Count` 比例算像素偏移让角色在格子间平滑滑动。

### 3.4 角色分层渲染

玩家外观由服务端 `S.ObjectPlayer` 下发的整数 ID 决定（`Armour`/`Weapon`/`Hair`/`WingEffect`/`MountType`/`TransformType`）。`SetLibraries()`（`PlayerObject.cs:252`）把每个 ID 映射到对应 `MLibrary` 并算偏移（不同职业/性别用不同库集与偏移量）。

`Draw()`（`PlayerObject.cs:4877`）按固定顺序分层叠加，**根据朝向调整前后层次**（背对镜头时武器/翅膀在身体之后，面向时在之前）实现正确遮挡：

```
DrawBehindEffects → DrawMount → [朝上/左:DrawWeapon] → DrawBody
→ DrawHead + DrawWings → [朝下/右:DrawWeapon]
```

各层用同一个 `DrawFrame`（已含朝向）加各自偏移（`ArmourOffSet`/`HairOffSet`/`WeaponOffSet`/`WingOffset`），保证所有层动作严格同步。

### 3.5 特效与飘字

- `Effect`（`Effect.cs:7`）：基础动画特效，`Library + BaseIndex + Count + Duration`，`DrawBlend` 叠加出图。子类 `Missile`(飞行弹道)、`BuffEffect`(增益光环)、`DelayedExplosionEffect` 等。挂在 `Owner.Effects`（跟随对象）或 `MapControl.Effects`（固定地面）。
- **触发**：施法动作内嵌特效（按 `CurrentAction + Spell` 直接画刀光），或服务端 `S.ObjectEffect/ObjectMagic/ObjectProjectile` 到达后往对象 `Effects` 添加。
- `SpellObject`：火墙/毒云/陷阱等地面持续法术，`Load` 里大 `switch(Spell)` 为每种设定图档/帧/混合/光照。
- `Damage`（`Damage.cs`）：伤害飘字，按剩余时间算 Y 偏移向上飘并淡出。
- 血条/名字/毒点都在基类 `MapObject`：`DrawHealth`（`Prguse2` 画血条）、`DrawName`（`MirLabel` 缓存，死亡变灰）、`DrawPoison`（按毒类型画头顶彩点）。

### 3.6 渲染顺序（画家算法）

`GameScene.DrawObjects()`（`GameScene.cs:10787`）按 Y 从上到下逐行渲染，**每行画完地图 tile 紧接着画该行格子里的对象**（`M2CellInfo[x,y].DrawObjects()`），这样下方对象天然遮挡上方，实现 2.5D 遮挡。最后单独一轮画所有血条保证血条在最上层。格内排序：物品 < 法术 < 其他。

## 第四部分 · 玩法对话框（UI ↔ 封包闭环）

对话框都在 `Client/MirScenes/Dialogs/`，继承 `MirImageControl`。数据双向流动：

```
服务端封包 → GameScene.ProcessPacket 分发 → 对应 dialog 的 Refresh*() 填充
用户操作   → Network.Enqueue(new C.xxx{...}) 发回服务端 → 服务端裁决回包 → 再刷新
```

### 典型闭环示例

**背包 InventoryDialog + 物品格子 MirItemCell**：

- 数据：内容存 `User.Inventory[]`，`RefreshInventory()` 把每格绑到 `MirItemCell` 显示；服务端 `S.MoveItem/EquipItem/GainedItem` 更新数组后触发刷新。
- 交互（都在 `MirItemCell`）：双击装备 → `C.EquipItem{Grid,UniqueID,To=槽位}`（按物品类型自动选槽）；用消耗品 → `C.UseItem`；拖拽 → `C.MoveItem{From,To}`；拆分 → `C.SplitItem`。
- 闭环：发 `C.EquipItem` → 服务端校验回 `S.EquipItem` → 改数组 → 刷新 + 角色 `Update` 重设外观库（装备外观立即变化）。

**NPC 对话 NPCDialogs**：

- 服务端脚本解析后发 `S.NPCResponse{Page}` → `NPCDialog.NewText(page)` 把文本/超链接渲染成可点按钮。
- 点 NPC 文本里的 `[@SECTION]` 链接 → `C.CallNPC{ObjectID, Key="[...]"}`，服务端跳到对应脚本段再回新 `NPCResponse`，形成对话循环。
- 买卖：`S.NPCGoods` → 商品列表；点购买 → `C.BuyItem`；卖/修理 → `C.SellItem`/`C.RepairItem`。

**任务 QuestDialogs**：

- 数据来自 `User.CurrentQuests`/`CompletedQuests`，由 `S.ChangeQuest` 等更新。
- NPC 头顶任务图标由 `NPCObject.UpdateBestQuestIcon()` 按玩家任务状态画感叹号/问号。
- 接任务 `C.AcceptQuest`、交任务 `C.FinishQuest`、放弃 `C.AbandonQuest`。

## 第五部分 · 客户端扩展点

### 5.1 新增一个 UI 对话框

1. 在 `Client/MirScenes/Dialogs/` 新建 `XxxDialog : MirImageControl`：构造里把标题栏/关闭按钮/子控件 `{ Parent = this }` 挂上，用某图档作背景，需拖动设 `Movable = true`，关闭按钮 `Click += (o,e)=>Hide()`。
2. 在 `GameScene` 构造里实例化并挂到场景树（`XxxDialog = new XxxDialog { Parent = this, Visible = false }`），自动获得绘制、事件分发、Dispose 级联。
3. 打开/关闭用 `Show()`/`Hide()`，由按钮或快捷键触发。
4. 需响应服务端数据则在 `GameScene.ProcessPacket` 加 case 调对话框更新方法（见 5.3）。
5. 物品类面板直接复用 `MirItemCell` 网格（传不同 `MirGridType`），免写拖拽逻辑。

### 5.2 加载并显示一个新图档资源

- 新 `.Lib` 文件：在 `Libraries`（`MLibrary.cs:10`）加 `static readonly MLibrary Xxx = new MLibrary(Settings.DataPath + "Xxx");`，并在 `LoadLibraries()`（必需即用）或后台 `LoadGameLibraries()`（可延迟）里加 `Xxx.Initialize(); Progress++;`。
- 显示：控件里 `Library = Libraries.Xxx; Index = n;`，或直接 `Libraries.Xxx.Draw(index, point, Color.White)`。无需手动管理纹理生命周期（懒加载建、`Clean` 自动回收）。
- 复用已有库的新帧直接用新 index，无需改 `Libraries`。

### 5.3 在客户端处理一个新封包

见 [02-通信协议 §10 步骤⑤](02-通信协议.md#10-端到端新增一个封包完整步骤)。要点：Shared 三件套（枚举/类/注册表）先齐，再在**会收到它的那个场景**的 `ProcessPacket` 加 case，写处理方法更新模型/对话框/对象，渲染由主循环 + 脏标记自动反映。
