## 第一部分 · 世界单例与主循环

### 1.1 启动链路

```
Server.MirForms/Program.cs:12  Main()
  → Packet.IsServer = true
  → Settings.Load()           读 Configs/Setup.ini
  → Application.Run(SMain)     WinForms 管理窗体
       SMain_Load → Envir.Edit.LoadDB()   把库读进"编辑实例"
       管理员点"启动服务器" → Envir.Start()
            Envir.Start (Envir.cs:3247): Running=true, 开后台线程跑 WorkLoop()
```

世界由单例 **`Envir.Main`**（`Envir.cs:46`）持有；`Envir.Edit`（`:48`）是编辑器用的第二实例（见 [05](05-内容开发总览.md)）。

### 1.2 WorkLoop 主循环

入口 `Envir.cs:1996`。`Time` 取自 `Stopwatch.ElapsedMilliseconds`，每次迭代开头重新读一次，全程单调递增，**所有定时判断都基于它**。`Now`（`:85`）= `启动UTC时间 + Time`，用于昼夜、每日重置等「日历语义」。

**循环前（一次性）**：初始化各定时器基准 → 多线程则建 `MobThreads[]` → `StartEnvir()` 加载世界数据 → `CanStartEnvir()` 启动前校验（失败停机）→ 启动怪物后台线程 → `StartNetwork()` 加载账号/行会并开监听端口。

**稳定运行段（`while (Running)`）每次迭代**：

```
1. 统计窗口        每 1000ms 刷新"每秒处理对象数"
2. 连接处理        Time 毫秒变化时(最多每毫秒一次):
                     AdjustLights() 算昼夜 → 逐个 Connections[i].Process()
                     → StatusConnections[i].Process()
3. 多线程怪物触发   唤醒后台线程跑 10ms,主线程亲自跑 MobThreads[0](构成栅栏)
4. 对象 20ms 时间片  用 current 游标遍历全局 Objects 链表,单次迭代最多花 20ms:
                     - 多线程下跳过非宠物怪物(它们交给工作线程)
                     - 满足 Time > OperateTime 才 Process() 然后 SetOperateTime()
                     - 时间到就中断,current 留在原地,下个迭代接着走
5. 地图处理        for 遍历 MapList[i].Process()
6. 龙系统          DragonSystem?.Process()
7. 全局周期系统    Process()  ← 所有"世界级定时玩法"都在这(见 1.6)
8. 定期落盘        每 SaveDelay 分钟: 存账号/DB/行会/商品/攻城
9. 广播           每 5 分钟在线人数,每 N 分钟跑马灯
```

> **循环没有 `Sleep`**，是忙循环，主线程持续满速运转。`Map.Process` 和全局 `Process()` 每迭代都调，但内部各自用 `Time >= xxxTime` 节流。

`Map.Process()`（`Map.cs:653`）每迭代做：刷怪 `ProcessRespawns()`、关超时的门、地图闪电/岩浆环境伤害、执行到点的 `ActionList` 延迟动作。

### 1.3 对象生命周期与调度

- **全局链表** `Envir.Objects`（`LinkedList<MapObject>`）是所有活动实体的总表。
- **加入** `MapObject.Spawned()`（`MapObject.cs:339`）→ `Objects.AddLast(this)`，多线程怪物再按地图所属线程加入工作线程子链表；初始 `OperateTime = Time + Random(OperateDelay)` 打散首次处理时刻。
- **移除** `MapObject.Despawn()` → 广播 `S.ObjectRemove` → 从链表移除 → 清 `ActionList`、令宠物 `Die()`。
- **地图侧存放**：`Map` 用 `Cells[x,y]` 二维数组存格子，每个 `Cell` 有 `List<MapObject> Objects` 和 `Attribute`（`Valid` 当且仅当属性为 `Walk`）。

**调度核心 —— `OperateTime` / `SetOperateTime`**（性能关键）：

- `OperateTime` 是该对象**下次允许被处理的最早时刻**。主循环只在 `Time > OperateTime` 时才调它的 `Process()`。
- `SetOperateTime()` 是抽象方法，每个子类决定「什么时候需要再被叫醒」：
  - `MonsterObject.SetOperateTime()`（`MonsterObject.cs:1232`）取默认 2000ms 后的基线，再扫描该怪所有未来事件时间点（`MoveTime`/`AttackTime`/`SearchTime`/buff/毒…），取**最近的**作为 `OperateTime`。空闲怪最多每 2 秒醒一次，极大省 CPU；有事的怪精确在下一事件点醒来。
  - `HumanObject.SetOperateTime()` 直接 `OperateTime = Time`（`HumanObject.cs:392`）——**玩家/英雄每 tick 都处理、不节流**，这正是它们必须留在主线程的原因（需要最高响应频率）。
- 惯用法 `target.OperateTime = 0;` = 「强制下一 tick 立即处理」（被攻击/受 buff 时立刻响应）。

### 1.4 多线程怪物处理

由 `Settings.Multithreaded`（默认 true）和 `Settings.ThreadLimit`（默认 2）控制。

- 每张地图构造时随机绑定一个线程号 `Thread = Random.Next(ThreadLimit)`（`Map.cs:47`）；怪物 `Spawned` 时按地图线程进对应工作线程的子链表。**同图怪物固定同线程**。
- `MobThreads[0]` 由**主线程**亲自跑；`1..N-1` 由独立后台线程跑。默认即 1 主 + 1 后台。
- **玩家/宠物/NPC/掉落/法术始终在主线程**。宠物（`Master != null`）被显式排除出工作线程——它与玩家强耦合，跨线程不安全。
- **栅栏语义**：主线程每迭代唤醒后台线程跑约 10ms，然后自己跑 `MobThreads[0]`，该调用自旋等所有后台线程停下才返回。于是每「帧」怪物处理是收敛的，之后才做地图/存盘。

**改怪物 AI 的跨线程注意事项**：

1. 怪物 AI 跑在工作线程，**不能直接安全地碰玩家集合、宠物、或别的地图线程的对象**；跨实体交互走 `ActionList`/`DelayedAction`。
2. 随机数用 `Envir.Random`（`RandomProvider`，内部 `ThreadLocal<Random>`，线程安全），不要自建共享 `Random`。
3. 跨地图迁移的怪物线程归属是已知注意点，源码有注释提醒。
4. `Settings.MonsterProcessWhenAlone` 控制周围无玩家时是否仍处理怪物。

### 1.5 启动加载与持久化（概览）

`StartEnvir()`（`Envir.cs:3302`）顺序：清空运行态 → **`LoadDB()`** 读 `Server.MirDB`（地图/物品/怪物/NPC/任务/技能等模板）→ 加载 Buffs → 扫 `Envir/Recipe/` → 建图 `CreateMap()` → 起始物品 → **`ReloadDrops()`** 读 `Envir/Drops/` → 龙系统 → 系统 NPC。随后 `StartNetwork()` 加载账号/行会/攻城再开端口。**账号晚于世界数据加载**，因为角色装备引用 `ItemInfo`。

保存全部由主循环每 `SaveDelay` 分钟触发，并在停机时强制保存，均采用「写临时文件 + 原子重命名 + 时间戳备份到 `Back Up/`」防损坏。数据模型细节见第五部分。

### 1.6 全局周期系统（扩展点预告）

所有「世界级定时玩法」都集中在 `Envir.Process()`（`Envir.cs:2309`），主循环每迭代调一次。现成范例：行会战倒计时、攻城（每 10s）、租赁到期、拍卖行、刷怪节拍、机器人定时脚本、每日重置 `ProcessNewDay()`。**新增全局定时事件就挂在这里**，详见 [09-地图与玩法系统](09-地图与玩法系统.md#新增全局定时世界事件)。

## 第二部分 · 实体层级

抽象基类 `MapObject`（`MapObject.cs:9`）定义地图上一切可见对象的契约。两条继承链：

```
MapObject (abstract)
├── HumanObject : MapObject          // 玩家/英雄共享基类(战斗代码几乎都在这)
│   ├── PlayerObject : HumanObject   // 真人玩家(薄,主要是网络/经验/死亡覆写)
│   └── HeroObject  : HumanObject    // 英雄/随从(半 AI 的"玩家")
└── MonsterObject : MapObject        // 怪物基类
    └── Monsters/ 下各子类           // 由 MonsterInfo.AI 选择
```

**关键认知**：`HumanObject` 承载了几乎全部战斗/属性/技能代码（`Attack`、`Magic`、所有技能效果方法、`RefreshStats`、`Attacked`、`Struck`、`ApplyPoison`）。`PlayerObject` 很薄，只覆写与真人/网络/经验相关的逻辑（如 `LevelUp`）。

基类关键成员：

- 抽象：`Race`(ObjectType)、`Name`、坐标/朝向/等级、`Health`/`MaxHealth`、`Process(DelayedAction)`、`Attacked(...)`、`Struck`、`Die()`、`GetInfo()`（生成 `S.ObjectPlayer/ObjectMonster` 广播包）、阵营判定 `IsAttackTarget`/`IsFriendlyTarget`。
- 通用状态容器**直接挂基类**、两链共享：`Buffs`（`List<Buff>`）、`PoisonList`（`List<Poison>`）。

`MonsterObject` 的可覆写 AI 钩子（子类定制的扩展点）：`ProcessAI()`、`ProcessTarget()`、`FindTarget()`、`Attack()`、`MoveTo()`、`Die()`、`Drop()`。详见 [07-怪物与AI](07-怪物与AI.md)。

## 第三部分 · 属性系统

### 3.1 表示

属性是枚举 `Stat : byte`（`Shared/Data/Stat.cs:85`），成员如 `MinAC/MaxAC`(物防)、`MinMAC/MaxMAC`(魔防)、`MinDC/MaxDC`(物攻)、`MinMC/MaxMC`(魔攻)、`MinSC/MaxSC`(道攻)、`Accuracy/Agility`(准确/敏捷)、`HP/MP`、`CriticalRate/CriticalDamage`、各种 `XxxRatePercent`(百分比加成)、`PoisonResist/Reflect` 等。

值容器是 `Stats`（`Stat.cs:1`），内部 `SortedDictionary<Stat,int>`：**读不存在的键返回 0，写 0 则删键**。`Add(Stats)` 逐键累加。每个 `MapObject` 持有一个 `Stats` 作为「最终属性」。

> 这个「零值不存储」的设计有一个重要副作用：**给系统加一个新属性几乎零成本**——加个枚举值即可，序列化天然向后兼容（见第五部分版本兼容）。

### 3.2 重算（脏标记式全量重算）

核心入口 `HumanObject.RefreshStats()`（`HumanObject.cs:1730`）：先 `Stats.Clear()` 清零，再按固定顺序叠加各来源：

```
1. RefreshLevelStats()      职业基础属性(Settings.ClassBaseStats 按等级公式算)
2. RefreshEquipmentStats()  遍历装备,每件属性 Add 进 Stats(同时算负重/外观/灯光)
3. RefreshItemSetStats()/MirSet  套装加成
4. RefreshSkills()          被动技能加成
5. RefreshBuffs()/GuildBuffs buff 加成(每个 buff 自带一个 Stats)
———— 以上是基础值,然后统一应用百分比 ————
6. HP/MP/MaxAC/MaxDC/... += 基础 * XxxRatePercent / 100
7. RefreshStatCaps()        封顶
8. 重算攻速 AttackSpeed
```

**触发时机**：任何影响属性的事件后调用——穿脱装备、火把耗尽、buff 增减、套装变化、升级等。它是全量重算，不做增量。

## 第四部分 · 战斗、技能、状态

### 4.1 一次普通攻击的数据流

```
① 客户端 C.Attack{方向,技能} → MirConnection.Attack → Player.Attack(方向,技能)
② 攻击者 HumanObject.Attack (HumanObject.cs:2848):
     - CanAttack 校验,隐身攻击加成,按技能扣 MP
     - Broadcast(S.ObjectAttack) 让周围播挥砍动画
     - AttackTime = Time + AttackSpeed (攻速节流)
     - damage = GetAttackPower(Stats[MinDC], Stats[MaxDC]) (Min~Max 随机+幸运)
     - 对目标 Cell 内对象逐个 target.Attacked(this, damage, DefenceType.ACAgility)
③ 受击者 Attacked(...) —— 伤害结算核心:
     - 命中判定 GetArmour: Random.Next(Agility+1) > attacker.Accuracy 则 miss
     - armour *= ArmourRate; damage *= DamageRate (受中毒影响,见 4.3)
     - + AttackBonus; Reflect% 概率反弹并 return; DamageReductionPercent 减伤
     - armour >= damage 判 Miss return 0
     - 暴击: Random < CriticalRate 时 damage += damage*CriticalDamage
     - 吸血 HPDrainRate 给攻击者回血; 能量盾/魔法盾削减
     - 记 LastHitter; PK 判定; ApplyNegativeEffects(武器附带毒/麻痹)
     - 发 S.Struck(自己受击) + 广播 S.ObjectStruck(硬直动画) + 伤害飘字
     - ChangeHP(armour - damage) 扣血
④ 死亡: ChangeHP 内 HP<=0 → Die()
     MonsterObject.Die (MonsterObject.cs:966):
       - 广播 S.ObjectDied; 有死亡脚本则 Call [@_DIE(index)]
       - 经验: EXPOwner.WinExp(经验,等级) 给归属者; 结算组队任务
       - 掉落: Master==null && EXPOwner!=null 时 Drop()
       - 清毒/扣刷新计数/全局怪数--
```

**物理 vs 魔法的区别**只在 `DefenceType` 和伤害来源属性：

- 物理近战用 `ACAgility`（吃 AC 护甲 + Agility 闪避），伤害取 `MinDC~MaxDC`。
- 魔法/道术用 `MAC`（吃魔防 MAC），伤害取 `MinMC~MaxMC` / `MinSC~MaxSC`。
- 魔法多为**延迟结算**：投递 `DelayedAction(DelayedType.Magic, ...)` 到 `ActionList`，到时由 `Process(DelayedAction)` → `CompleteMagic` 真正落地；普攻多为即时 Cell 命中。

### 4.2 技能/魔法系统

**数据**：`MagicInfo`（技能定义：`Spell` 枚举 id、蓝耗、射程、威力、各级升级所需经验）；`UserMagic`（玩家已学技能实例：`Level`/`Experience`/`CastTime`，方法 `GetPower`/`GetDamage`/`GetDelay`）。`Spell` 是技能枚举（`Shared/Enums.cs`）。

**施放路径**：

```
客户端 C.Magic{Spell,方向,TargetID,坐标}
  → MirConnection.Magic (:1567) 做节流(冷却没到丢回 _retryList)
  → HumanObject.Magic (HumanObject.cs:3400):
      - CanCast/已学/射程校验; 解隐
      - 扣蓝 ChangeMP(-cost); 设 SpellTime 冷却
      - 大 switch(spell) 分发到对应效果方法 (:3499):
          Fireball(target,magic) / Healing(...) / ElectricShock(...) ...
          多数构造 DelayedAction(DelayedType.Magic, ...) 入 ActionList
  → Process(DelayedAction) 取到时动作 → CompleteMagic(:5903):
      对目标 Attacked / AddBuff / ApplyPoison; 广播 S.ObjectMagic/ObjectEffect
```

**练级**：成功施放后给 `UserMagic.Experience` 加经验（受 `SkillGainMultiplier` 影响），满则升级并广播。被动技能随等级增强（如刺杀触发概率 `Random.Next(12) <= magic.Level`）。

### 4.3 状态系统：Buff 与 中毒

**Buff**（`List<Buff> Buffs` 挂基类）：每个 `Buff` 含 `Type(BuffType)`、`ExpireTime`、`Paused`、`FlagForRemoval`，以及**一个 `Stats` 增益块**（`RefreshBuffs` 把它叠进总属性的来源）。

- 施加 `AddBuff(BuffType, caster, durationMs, Stats)`，加完通常触发 `RefreshStats`。
- 每 tick `ProcessBuffs()`（`HumanObject.cs:397`）遍历，到期或被标记则移除；特殊 buff 有副作用（如隐身到期清 `Hidden`）。

**中毒 Poison**（`List<Poison> PoisonList`）：`Poison` 含 `PType(PoisonType)`、`Duration`、`TickSpeed`、`Value`、`Owner`。

- 施加 `ApplyPoison`（`HumanObject.cs:7380`）：按 `PoisonResist` 抗性可能免疫；绿毒可被 MAC 削减；同类型毒按强度/时长规则刷新而非叠加（弱毒不顶强毒、冰冻/麻痹不可续期防永控）。
- 每 tick `ProcessPoison()`（`HumanObject.cs:650`）：先把 `ArmourRate/DamageRate` 重置为 1；遍历毒按 `TickSpeed` 触发——**绿毒/流血**扣血飘字，**红毒**降 `ArmourRate -= 0.10`（破甲），**Stun** 提 `DamageRate += 0.20`（易伤）——这两个系数正是 4.1 里 `Attacked` 乘算的来源。聚合后体色变化则广播 `S.ObjectPoisoned`。

### 4.4 移动与视野广播

`C.Turn/Walk/Run` → `MirConnection` → `Player.Turn/Walk/Run`，校验目标格可走（阻挡/门/定身/麻痹）、更新坐标与格子登记，广播 `S.ObjectTurn/ObjectWalk/ObjectRun`。

视野广播机制见 [02-通信协议 §6.3](02-通信协议.md#63-广播给周围玩家)：`Globals.DataRange` 是全局一致的「视野/交互半径」，同时用于移动广播、伤害广播、状态广播、经验归属判定。

## 第五部分 · 数据模型与持久化

### 5.1 存储架构

服务端持久化**不是 SQL**，是三类载体：

1. **两个二进制平铺文件**：`Server.MirDB`（游戏静态模板）、`Server.MirADB`（账号+角色+物品实例）。
2. **`Envir/` 下文本数据树**：Drops/Quests/Recipe/Routes/Values/NameLists/NPCs/Goods…（路径见 `Settings.cs:18-35`）。
3. **`Configs/*.ini`**：Setup.ini、ExpList.ini、BaseStats*.ini 等数值表。

### 5.2 模板类的统一范式

所有「模板」类遵循同一范式：`int Index`（主键）+ `string Name` + `构造(BinaryReader)` 反序列化 + `Save(BinaryWriter)` 序列化，**彼此通过 Index 关联**（加载后靠 `Envir.GetXxxInfo` 绑定指针）。

| 模板 | 代表什么 | 关键字段 |
|---|---|---|
| `ItemInfo`(`Shared/Data/ItemData.cs`) | 物品模板 | Type/Grade/Shape/Image/Durability/Weight/Price/StackSize/Bind/Stats |
| `MonsterInfo` | 怪物模板 | Image/**AI**/Level/ViewRange/AttackSpeed/Experience/Stats/**DropPath** |
| `MapInfo` | 地图模板 | FileName(.map)/Light/内嵌 SafeZones/Movements/Respawns/NPCs/MineZones |
| `NPCInfo` | NPC 放置点 | FileName(脚本)/MapIndex/Location/Image/任务关联 |
| `MagicInfo` | 技能模板 | Spell/蓝耗/各级所需等级与经验/威力/射程 |
| `QuestInfo` | 任务模板 | Name/Group/FileName/NpcIndex/各种要求(+文本里的目标/奖励) |
| `RecipeInfo` | 合成配方 | 产物/材料/工具/要求/几率 |

数值容器 `Stats` 被 ItemInfo/MonsterInfo/UserItem 共用，序列化为「`int count` + 每项`(byte key,int value)`」，零值不存。

### 5.3 模板 vs 实例

| 模板（存二进制库，全服一份） | 实例（挂玩家/世界，存当前状态） |
|---|---|
| `ItemInfo` | `UserItem`：`UniqueID`(全局唯一)、`ItemIndex`(→ItemInfo)、`CurrentDura`、`Count`、`AddedStats`(精炼)、`Awake`、`Slots[]`(镶嵌) |
| `MonsterInfo` | `MonsterObject`(运行期,不持久化,靠 RespawnInfo 刷出) |
| `MagicInfo` | `UserMagic`(带 Level/Experience) |
| `QuestInfo` | `QuestProgressInfo`(带击杀计数) |

`UserItem` 反序列化后只有 `ItemIndex`，由 `Envir.BindItem` 按 index 接上 `Info` 指针。**模板字段绝不复制进实例**，实例读属性走 `GetTotal(stat) = AddedStats[stat] + Info.Stats[stat]`。

### 5.4 版本兼容（新增字段必读）

版本常量在 `Envir.cs:55-57`：`MinVersion=60`、`Version=117`、`CustomVersion=0`。文件头两个 int 读入 `Envir.LoadVersion`/`LoadCustomVersion`。守门：`LoadVersion < MinVersion` 拒载（太旧），`> Version` 拒载（库比程序新）。

**所有构造器靠 `LoadVersion` 做字段门控**。新增字段的实操规则：

1. **`Envir.Version` 加 1**（如 117→118）。
2. 在该 Info 的 `Save` **末尾追加** `writer.Write(新字段)`（不能插中间，二进制位置相关）。
3. 在构造器**末尾追加** `if (Envir.LoadVersion >= 118) 新字段 = reader.ReadXxx();`，老档版本号小于 118 自动跳过、保留默认值。
4. **属性数值优先塞进 `Stats` 字典**（加一个 `Stat` 枚举值），借其 count+kv 格式天然向后兼容、零迁移成本。
5. 引用其它实体一律存 **Index/名字**，加载后 `Bind` 重新接指针，不要存对象。
6. 私有/魔改字段可走 `CustomVersion` 独立版本轴，不与上游 `Version` 冲突。

> 历史迁移分支（如 `version <= 84` 的旧布局）是兼容旧档的代码，新增逻辑别动它们，只在最新版本号后追加。

### 5.5 账号与角色存档

```
AccountList → AccountInfo → Characters → CharacterInfo → {Inventory/Equipment/
              Magics/CurrentQuests/Flags/Pets/Buffs/Mail/Heroes/...}
```

- `AccountInfo`：账号级容器，含密码(加盐)、仓库密码(v117)、`List<CharacterInfo>`、**账号共享仓库** `Storage[]`、Gold/Credit。
- `CharacterInfo`：单角色全部存档——基本属性、位置/绑定点、**物品**（`Inventory[46]`/`Equipment[14]`/`QuestInventory`/`Trade`/`Refine`，均 `UserItem[]`）、**技能** `Magics`、**任务**（进行中 `CurrentQuests`、已完成 `CompletedQuests`）、**标志位** `bool[] Flags`（NPC 脚本/配方用它判断条件）、宠物/buff/邮件/好友/英雄/婚姻师徒等。

整棵树在 `SaveAccounts` 里递归写出到 `Server.MirADB`。

### 5.6 Envir 文本数据文件

与代码解耦的内容数据，可热重载：

| 目录/文件 | 用途 | 加载者 |
|---|---|---|
| `Envir/Drops/` | 怪物/钓鱼/觉醒/强化箱掉落表 | `DropInfo.Load`，入口 `Envir.ReloadDrops()` |
| `Envir/Quests/` | 任务目标/奖励/描述正文 | `QuestInfo.ParseFile` |
| `Envir/Recipe/` | 合成配方（每配方一文件） | `RecipeInfo.LoadIngredients` |
| `Envir/Routes/` | 怪物巡逻路径 | `Map.LoadRoutes()` |
| `Envir/NameLists/` | 名单（白/黑名单） | NPC 脚本动作/HTTP 接口 |
| `Envir/Values/` | NPC 脚本读写的键值表 | NPC 脚本 value 操作 |
| `Envir/NPCs/` | NPC 行为脚本 | `NPCScript`/`NPCSegment` |
| `Configs/*.ini` | 等级经验、职业基础属性、随机属性等数值表 | `Settings.Load` 及子加载器 |

> 注意：职业基础属性/经验表实际从 `Configs/*.ini` 读，`Envir/Values` 仅服务 NPC 脚本的键值存取，两者别混淆。

格式细节与「加内容动哪些数据」见第二册各篇。
